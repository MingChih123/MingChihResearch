# 研究進度整理(給 Claude 聊天版做簡報用)

> 使用方式:把這整份貼給 Claude 聊天版,請它幫忙做進度報告簡報。
> 簡報要用**英文**,約 3 頁,內容簡單明瞭。

---

## 1. 研究在做什麼

- **任務**:判斷一張迷因(圖片 + 圖上的文字)是不是仇恨迷因,模型回答 Yes / No。
- **情境**:社群平台的自動審核。使用者上傳迷因 → 系統用 OCR 抽出圖上的文字 → 把「圖片 + 文字」一起交給視覺語言模型判斷。
- **模型**:Qwen2-VL-2B-Instruct,**完全凍結、不訓練、不微調**(training-free)。
- **威脅**:攻擊者在圖片上加人眼看不出的擾動(對抗攻擊),讓仇恨迷因被判成「無害」而通過審核。
- **防禦**:只在推論階段(test-time)做,不訓練模型:
  - 換問法:用 3 種不同說法問同一個問題
  - 加雜訊:對圖片加隨機雜訊,問好幾次
  - 投票:把多次回答合起來決定
- **資料**:Facebook Hateful Memes 的 dev set,500 張(仇恨 250 / 非仇恨 250)。

---

## 2. 這段時間做的改善

1. **修正了一個程式錯誤,舊的部分結果作廢。**
   「加權投票」原本比的 token 和模型實際輸出的不一樣(差一個空格),導致它系統性偏向回答 Yes。之前看起來很高的恢復率(66%–100%)是這個錯誤造成的,修正後已全部重跑。
   (這點**不放進簡報**,口頭知道就好。)

2. **評估方式變嚴謹。**
   - 從「抽 200 張」改成用 dev 全部 500 張。
   - 除了準確率,也算 recall、F1、混淆矩陣。
   - 分開計算「救回多少」和「把原本答對的弄錯多少(副作用)」。
   - 要調的參數改在 train set 上選,dev 只報最後結果(避免在測試資料上調參)。

3. **做了消融實驗(ablation)**:檢查「換問法」的效果到底是來自投票,還是某一個問法比較好。

4. **把攻擊改成真實可行的版本。**
   - 舊攻擊:直接改模型內部的張量(已經切塊、正規化過的資料),現實中攻擊者做不到。
   - 新攻擊:直接改**圖片像素**,每個像素最多改 8/255(人眼幾乎看不出來),存成 PNG 檔,再像使用者上傳一樣讀回來判斷。
   - 另外測試「平台把圖片轉存成 JPEG」的情況,JPEG 壓縮也當作一個簡單的對照組(baseline)防禦。

5. **試過但沒有用的方法(已放棄)**:
   - 用模型輸出的 logit 差距當信心分數做「加權投票」→ 沒有比一般多數決好,反而更常把答對的改錯。
   - 調整判斷門檻(threshold calibration)→ 幾乎沒有改善。

## 3. 結果

### 3.1 乾淨圖片(沒有攻擊),dev 500 張

| Method | Accuracy | Recall | F1 |
|---|---|---|---|
| No defense | 59.2% | 24.4% | 0.37 |
| Image noise + majority vote | 57.6% | 20.8% | 0.33 |
| 3 paraphrased questions + majority vote | 61.4% | 32.0% | 0.45 |
| Best single paraphrased question | 62.8% | 38.0% | 0.51 |
| Flag if any question says "Yes" | 61.4% | 44.8% | 0.54 |

**指標意思:**
- **Accuracy(準確率)**:500 張裡答對的比例。
- **Recall(召回率)**:250 張仇恨迷因裡,模型抓到幾張。
- **F1**:recall 和 precision(標成仇恨的裡面真的是仇恨的比例)的平衡分數,0~1,越高越好。

**名詞:**
- **Best single paraphrased question**:三個改寫問法裡,單獨用表現最好的那一個(不投票)。
- **Flag if any question says "Yes"(any-Yes 規則)**:三個問法只要有一個說 Yes,就標記成仇恨、送人工審核。

**重點:**
- 模型本身很保守,只抓到 24% 的仇恨迷因。
- 換問法有幫助;但單用最好的那個問法就比三個問法投票還好 → 提升主要來自「一個問得比較好的問題」,不是投票本身。
- any-Yes 規則抓到最多仇恨迷因(44.8%),代價是誤判正常迷因變多。審核情境下漏掉仇恨迷因的代價比較高,所以這個規則可能比較實用。
- 加雜訊在乾淨圖片上沒有幫助。
- 注意:「最好的問法」和「any-Yes」是在 dev 上比出來的,之後要改在 train 上選。

### 3.2 真實圖片攻擊

**攻擊比較:**

| | Old attack | New attack |
|---|---|---|
| What it changes | Model's internal tensor | Image pixels |
| Budget | Not in pixel units | 8/255 per pixel |
| Saved as an image file | No | Yes (PNG) |
| Success rate | 46% (28/61) | 62% (36/58) |
| After JPEG re-compression | Not tested | 28% (16/58) |

(攻擊對象:模型原本判對的仇恨迷因。另有 3 張光是縮放存檔就從 Yes 變 No,不算攻擊成功,已排除。)

**防禦結果(36 張被攻擊成功的迷因,能救回幾張):**

| Defense | Recovered |
|---|---|
| JPEG re-compression (baseline) | 56% (20) |
| Flag if any question says "Yes" | 44% (16) |
| Image noise + majority vote | 36% (13) |
| Paraphrase × noise + majority vote | 33% (12) |
| Paraphrase + majority vote | 8% (3) |

**重點:**
- 新攻擊比較真實,也比較強(62% 成功)。
- 但轉存成 JPEG 後只剩 28% 有效,而很多平台上傳時本來就會轉 JPEG。
- 最簡單的 JPEG 壓縮救回最多(56%),**目前我們的方法還沒有贏過 JPEG**。我們的方法裡 any-Yes 最好(44%)。

## 6. 關於相關論文(R-TPT)

- 我們放棄的是「用第一個 token 的 logit 差距當信心分數」這個做法,實驗顯示它不是可靠的信心指標。
- R-TPT 的「依可靠度加權集成」想法本身沒有被否定。R-TPT 衡量可靠度的方式和我們用的不同,詳細做法要回原論文確認。
- 所以 R-TPT 仍然可以當相關研究引用,說明我們參考了它的加權集成想法,但在這個任務上,用 logit 差距加權沒有帶來好處。
